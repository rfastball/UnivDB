## 1. 문제 정의

### 1.1 이름이 반환하는 조용히 틀린 결과

프로젝트의 최상위 설계 원칙은 다음과 같이 명문화되어 있다.

> "조용히 틀린 결과"가 최악의 실패 양식이다. (`UnivDB_design_decisions_202607.md` §0)

이 원칙은 코드 전반에서 일관되게 집행된다. 컬럼명 오타는 `Err 9999`, 허용 목록 밖 연산자는 `Err 9999`, 세대 불일치 파생 구조는 `Err 9999`.

**그러나 이름 자체는 이 원칙의 적용을 받지 않고 있다.**

`DB`라는 기표는 읽는 즉시 다음을 약속한다.

| 약속 | 실제 |
|---|---|
| 트랜잭션 / 롤백 | 없음. `Update`가 중간에 실패하면 절반 적용 상태 |
| 영속성 | 없음. 프로세스 종료 시 증발 (`ClearDB`가 그 증거) |
| 격리 | 없음. `RegisterTable` 이후 시트 변경을 `DumpToSheet`가 조용히 덮어씀 |
| 제약조건 | 없음. `clsTableBuilder`는 존재하지 않는 컬럼을 조용히 생성 |
| 쿼리 최적화 | 없음. `Where`를 먼저 호출하라고 **사람에게** 지시 (101 §5) |

신규 사용자가 `Rollback`을 찾는 것은 사용자의 실수가 아니다. **이름이 만든 기대에 대한 정확한 반응이다.**

### 1.2 명명 체계가 `DB`를 서술어 자리에 고정한다

프로젝트 패밀리의 명명 문법은 다음과 같다.

```text
Univ + Filter       (프로젝트 기원. 범용 필터)
Univ + Contractor   (계약 관리)
Univ + Dbg          (디버그 인프라)
Univ + DB           (본 라이브러리)
```

이 문법에서 `Univ`는 의미가 표백된 패밀리 표지이고, **접미사 슬롯이 "이것이 무엇인가"를 나르는 유일한 자리다.**

따라서 `DB`는 무해한 장식이 아니다. 명명 체계 자체가 그것을 **주장으로 읽으라고 강제한다.** 저자가 의도하지 않았더라도, 그 자리에 놓이면 약속이 된다.

### 1.3 문서가 이름의 부채를 상환하고 있다

`UnivDB_101.md` §9 "자주 걸리는 함정"은 5개 항목 중 최소 3개가 설계·명명이 만든 함정이다. 특히:

- `UnivDB.Join`의 기본값은 `jtInner`, `Report(...).JoinTable`의 기본값은 `jtLeft` — 문서로 때우고 있는 불일치
- "Query는 지연, Report는 즉시" — 이름에서 드러났어야 할 정보를 산문이 설명

문서 분량은 API가 요구하는 것이다. 함정 목록은 **리팩토링 백로그를 문서 형태로 미뤄둔 것**이다.

## 2. 이 라이브러리의 실제 정체

### 2.1 코드가 증언하는 계보

발생사는 다음과 같다 (저자 진술).

```text
필터를 대량·고속으로 → 집합 연산 구현 → 집합 연산을 제대로 쓰려고 체이닝 → 체이닝이 본진
```

이 계보는 코드에 화석으로 남아 있다.

**증거 1 — 내부 실행 표현.** 최적화를 위해 파고든 바닥에 있던 것은 집합이다.

> `HashIndex` / `RowList` / **`RowSet`** (`UnivDB_refactor_plan.md` §0)

현행 프로토타입은 조인 키 비교에 `clsSet.Compare / Intersection`을 직접 사용한다 (동 문서 §1).

**증거 2 — 조인 8종.** `jtLeftAnti`(차집합), `jtLeftSemi`(존재 한정), `jtRightSemi`, `jtFull`까지 완비. 이는 관계 대수의 어휘다.

**증거 3 — 결여 목록.** 열(column) 중심 연산이 빈약하다.

| DataFrame 라이브러리의 표준 기능 | UnivDB |
|---|---|
| pivot / reshape | 없음 |
| 타입 추론 (`InferTypes`) | 없음 |
| 결측 정제 (`Clean` / `Dropna`) | 없음 |
| 벡터화 열 산술 | `Compute` 하나. 이항 `+ - * / &` 뿐 |
| semi / anti 조인 | **8종 완비** |

### 2.2 귀결: DataFrame이 아니라 관계 대수 엔진

표면의 fluent 체이닝이 pandas를 닮았으나, **무게중심이 행/집합이지 열이 아니다.**

정확한 카테고리는 다음과 같다.

> **Excel 시트 위의 관계 대수 엔진.**
> (선택·투영·조인·집합 연산·집계를 인메모리 2D Variant 배열 위에서 수행하고, 시트로 환원한다)

이 문장의 장점은 **없는 것에 대해 아무 약속도 하지 않는다**는 점이다. 관계 대수는 트랜잭션을 약속하지 않고, pivot을 약속하지 않으며, 영속성을 약속하지 않는다.

### 2.3 fail-fast의 구조적 기원 (중요)

이 절은 재명명의 핵심 근거이므로 별도로 기술한다.

**집합 연산의 고유한 실패 양식은 빈 집합이다.**

- 교집합이 비어 0행 → 유효한 결과
- 컬럼명 오타로 0행 → 버그
- **두 경우가 반환값에서 구별되지 않는다**

반면 DataFrame 라이브러리는 열을 지시하므로 오타가 즉시 `KeyError`로 드러난다. 집합을 지시하는 순간, **오타가 유효한 답으로 위장한다.**

따라서 `Err 9999`는 나중에 덧붙인 철학이 아니다. **집합 연산 라이브러리를 만들면 반드시 마주치는 구조적 문제에 대한 필연적 응답이다.**

"조용히 틀린 결과가 최악의 실패 양식"이라는 프로젝트 제1원칙은, 이 라이브러리가 관계 대수 엔진이기 **때문에** 존재한다. 이름이 `DB`인 한, 이 인과는 문서 어디에서도 설명되지 않는다.

## 3. 후보 검토

| 후보 | 평가 | 판정 |
|---|---|---|
| `UnivDB` (현행) | 없는 계약 4종을 약속. §1.1 | **기각** |
| `Univ` (접미사 제거) | 접미사 슬롯이 의미를 나르는 패밀리 문법을 위반. 멤버가 가문 루트를 참칭 (`UnivContractor` 사용자에게 혼동) | 기각 |
| `UnivFrame` | DataFrame 계보를 주장. 없는 pivot·타입 추론·`Clean`을 찾으러 오게 됨. §2.1 | 기각 |
| `UnivSet` | 기원(집합 연산)을 명명. 그러나 기원은 소유자의 진실이지 사용자의 진실이 아니다. 사용자가 손에 쥐는 것은 `RowSet`이 아니라 `clsTable`이며, 호출하는 것은 `.Intersect`가 아니라 `.Where`다 | 기각 |
| `UnivFilter` (기원 복귀) | 조인 8종·GroupBy·Upsert를 포괄하지 못함. 그 이름이 정직했던 것은 그때 그 물건이 필터였기 때문 | 기각 |
| `UnivStrict` / `UnivContract` | 철학은 캐치프레이즈의 일이다. 이름이 형용사가 되면 호출부가 매 줄 자기 자랑을 한다 (`UnivStrict.Query(...)`) | 기각 |
| **`UnivTable`** | 사용자가 손에 쥐는 명사. `clsTable`이 유일한 자료구조라는 사실과 일치. 접미사 슬롯을 정직하게 채움. 없는 기능을 약속하지 않음 | **채택** |

### 3.1 `UnivTable`의 근거

1. **유일 자료구조와의 일치.** 모든 데이터는 `clsTable`에 담긴다. 진입점 4개(`Query`/`Report`/`Builder`/`clsTable` 직접)는 전부 이 하나를 다루는 표면이다. 파사드가 `UnivDB`인 것은 순수한 불일치다.
2. **101 §4의 자기설명화.** "테이블 하나, 작업 표면 넷"이라는 문장이 이름에서 직접 읽힌다.
3. **의미의 정확한 두께.** `Table`은 "행과 열을 가진 것"만 약속한다. 트랜잭션도, 영속성도, pivot도 약속하지 않는다.
4. **패밀리 문법 보존.** `Univ` + 명사. `UnivContractor`, `UnivDbg`와 동일 형식.

## 4. 부수 제안: 카테고리 문장과 캐치프레이즈

`UnivDB_101.md` §1의 현행 첫 문장은 오해의 발원지다.

```diff
- UnivDB는 Excel 배치 작업을 위한 인메모리 DB 라이브러리입니다.
+ UnivTable은 Excel 시트 위의 관계 대수 엔진입니다.
+ 게으르고 무뚝뚝합니다 — 시키기 전엔 안 돌고, 틀리면 바로 소리칩니다.
```

- 1행: 카테고리. 거짓말하지 않는다.
- 2행: 철학. `Query`의 지연 실행(게으름) + fail-fast(무뚝뚝함)를 한 문장에 압축한다.

**출처 표기 의무.** 2행의 문장 구조는 R의 `tibble`이 확립한 것이다 (`lazy and surly: they do less and complain more`). 채택 시 README 각주에 차용 사실을 명기할 것.

## 5. 비-목표 (Non-goals)

이 제안이 **요구하지 않는** 것을 명시한다. 범위 확장을 방지하기 위함이다.

1. **`Univ` 접두사는 변경하지 않는다.** 이 형태소는 의미 표백(semantic bleaching)이 완료되어 현재 아무것도 주장하지 않는다. 패밀리 표지로 정상 작동 중이다.
2. **`Univ = Universal`이라는 어원을 문서에 기록하지 않는다.** 표백된 형태소를 재동기화하면 죽은 약속("어디에나 쓰인다")이 되살아난다. 본 라이브러리는 `Range`를 입력받아 `DumpToSheet`로 종결되는, Excel에 단단히 결속된 물건이다. **각주에도 쓰지 말 것** — 각주에 쓰는 순간 선언이 된다.
3. **ACID 구현은 이 제안의 범위가 아니다.** `UnivDB_ACI_design_notes_202607.md`가 별도 트랙으로 다룬다. 단, 본 제안이 채택되면 그 메모의 §7(부수 관찰)은 이 문서로 이관하고 §7을 삭제한다.
4. **클래스명(`clsTable`, `clsQuery` 등)은 변경하지 않는다.** 파사드 모듈명만 대상으로 한다.
5. **API 시그니처는 변경하지 않는다.**

## 6. 실행 계획

### 6.1 마이그레이션 전략: shim 유지

VBA에서 전면 개명은 기존 매크로 전부를 컴파일 에러로 만든다. 따라서 **모듈 분리 + 포워딩**을 채택한다.

```vb
' modUnivTable.bas  — 신규 정식 파사드
Public Function Query(ByVal Target As Variant) As clsQuery
    ' 실제 구현
End Function

' modUnivDB.bas  — deprecated shim (당분간 유지)
'@Deprecated: UnivTable을 사용하십시오. v3.0에서 제거 예정.
Public Function Query(ByVal Target As Variant) As clsQuery
    Set Query = UnivTable.Query(Target)
End Function
```

- 기존 사용자 코드(`UnivDB.Query(...)`)는 **무변경으로 동작한다.**
- 신규 코드는 `UnivTable`을 사용한다.
- `xlam` 참조 시 `Public` 함수 이름 충돌은 발생하지 않는다 (모듈 한정 호출 `UnivTable.Query`가 강제되는 것이 아니라 허용되는 형태이나, 두 모듈에 동명 `Public` 함수가 존재하면 **비한정 호출 시 모호성 컴파일 에러**가 발생한다 — §7 위험 참조).

### 6.3 수행 시점 권고

`UnivDB_refactor_plan.md`의 Phase 경계에서 수행할 것. **Phase 중간에 착수하지 말 것.**

근거: 리팩토링 진행 중에는 diff가 이미 크다. 개명 diff가 섞이면 실행 표현 전환(Dictionary → HashIndex/RowSet)의 회귀 원인 추적이 오염된다. 개명은 순수 기계적 치환이므로 **독립 커밋 1개**로 격리되어야 한다.

권장: Phase 0 착수 직전 또는 Phase 8 완료 직후.

### 6.4 수락 기준

- [ ] `UnivTable.*` 호출로 101 §3 QuickStart 매크로가 동작한다
- [ ] `UnivDB.*` 호출로 동일 매크로가 **경고 없이** 동작한다 (하위 호환)
- [ ] 회귀 테스트 전량 통과, 벤치마크 회귀 없음 (개명은 성능에 영향이 없어야 한다)
- [ ] 코드베이스 내 `UnivDB.` 잔존 참조 0건 (shim 모듈 내부 제외)
- [ ] 문서에 `인메모리 DB` 문자열 잔존 0건

## 7. 위험 및 완화

| 위험 | 심각도 | 완화 |
|---|---|---|
| 두 모듈에 동명 `Public` 함수 존재 → 비한정 호출(`Query(...)`) 시 모호성 컴파일 에러 | **높음** | 코딩 컨벤션(Reference §10)에 **모듈 한정 호출 강제**를 명문화. shim의 함수를 `Public`이 아닌 별도 처리로 검토. 착수 전 VBE에서 실증 확인할 것 |
| shim이 영구화되어 두 이름이 공존 | 중 | shim 상단에 제거 목표 버전(v3.0) 명기. 릴리스 노트에 deprecation 공지 |
| 외부 배포본(`.xlam`) 참조 경로를 쓰는 사용자 코드 파손 | 낮음 | shim이 흡수. 참조 라이브러리명(`UnivDB.xlam`) 자체는 별도 결정 사항 |
| 문서 파일명 개명 시 볼트·타 프로젝트의 링크 파손 | 낮음 | 작업 6은 선택 항목. 링크 검색 후 일괄 처리하거나 보류 |
| "관계 대수 엔진"이 SQL 파서 존재를 기대하게 함 | 낮음 | 101 §1 2행("게으르고 무뚝뚝")과 §4(진입점 4종)가 즉시 실체를 보여줌. 필요 시 "SQL은 없습니다 — 메서드 체인입니다" 한 줄 추가 |

## 8. 인간 결정이 필요한 항목

코드 에이전트가 단독 판단하지 말 것.

1. **shim 유지 기간과 제거 버전.** v3.0이 적절한가?
2. **배포본 파일명** `UnivDB.xlam` → `UnivTable.xlam` 변경 여부. 사용자의 참조 설정을 파손한다.
3. **문서 파일명 개명(작업 6)** 수행 여부.
4. **캐치프레이즈 채택 여부.** tibble 차용에 대한 저자의 판단.

## 9. 판단 요청

본 제안의 핵심 주장은 하나다.

> **fail-fast를 제1원칙으로 삼는 라이브러리가, 자기 이름에서 조용히 틀린 결과를 반환하고 있다.**

`Err 9999`가 컬럼명 오타에서 멈출 이유가 없듯이, 이름에서 멈출 이유도 없다.

승인 시 §6 실행 계획에 따라 진행하고, 본 문서를 `UnivTable_design_decisions_202607.md`(가칭)로 승격한다.
